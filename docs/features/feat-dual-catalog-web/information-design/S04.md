# S04 Workspace 設定 (認証の接続) 情報設計シート

## 利用文脈

workspace-admin。年に数回、認証基盤 (Google Cloud Console) 側の設定を作るか、期限の来た合鍵 (client secret) を入れ替えるために開く。**失敗すると全員がサインインできなくなる**画面で、開く人は緊張している。手を動かす場所が Hub と Google Cloud Console の 2 つに分かれるのが、この画面の設計を決める最大の条件。端末は wide が主。

## 画面プロファイル

Surface: `S04.AUTH` / route: `/settings/auth`。role、task-mode、density、wide/middle/narrow pattern、sticky policy は `docs/screen-inventory.md` の同 surface 行だけを正本とする。

## 表示項目とグループ

| 面 | 項目 | 表示加工 | 可視ラベル | accessible name/description |
|---|---|---|---|---|
| 1. Google 側の手作業 | 承認済みのリダイレクト URI | 値 + 「コピー」ボタン | 用語 | 「顧客所有方式の callback URL をコピー」 |
| 1. | 有効化する scope | カンマ区切り | 用語 | 用語 + 説明 |
| 1. | 参考: 共有方式の callback URL | 値 + 「コピー」ボタン | 用語 | 「共有方式の callback URL をコピー」 |
| 接続 1 件 | 状態 | `StatusChip domain="idpCredential"` | チップの語 | 「この接続の状態」 |
| 接続 1 件 | ログインに使われているか | 「この接続でログインが解決されます」/「この接続はログインに使われていません」 | 文そのもの | — |
| 接続 1 件 | client ID / secret の末尾 / 最後にテストした日時 / 最後に更新した日時 | 定義リスト。未実施は「未実施」、未登録は「未登録」 | 用語 | 用語 + 説明 |
| 接続 1 件 | 現行 secret を接続テスト / 有効化する / 無効化する | ボタン 3 つ | ボタンの語 | — |
| secret の入れ替え | 新しい client secret | 伏字入力。説明「登録しても切り替わりません。テストに合格してから有効化で切り替えます。」 | ラベル | ラベル + 説明 |
| secret の入れ替え | 登録 / テスト / 取り消し | ボタン | ボタンの語 | — |

**secret 本体は絶対に表示しない。** 出すのは末尾 4 文字だけで、これは「どの合鍵か」を見分けるためであり、値を読むためではない。

**Hub がやらないことを面の説明に書く。** 「OAuth client の作成・変更・削除は Google Cloud Console でのみ行えます。Hub は下の値を提示するだけで、Google 側の設定は代行しません。」— この一文が無いと、Hub のボタンを押せば Google 側も揃うと読める。

同じ理由で、切り替え後の案内にも「Google Cloud Console で旧 secret を失効させてください。失効の完了は Hub からは確認できません。」と、**Hub から見えない範囲**を明示する。

## 入れ替えの段取りを画面の構造にする

| 段 | 画面の状態 | いま何が起きているか |
|---|---|---|
| 1 登録 | 入力欄 + 「新しい secret を登録する」 | まだ切り替わっていない |
| 2 テスト | 「新しい secret をテスト」+ 「ローテーションを取り消す」 | **現在のログインは今までの設定で継続しています** (強調して明示) |
| 3 切り替え | 「新しい secret へ切り替える」が押せるようになる | テストに合格した接続だけ有効化できる |

テストに合格するまで有効化ボタンを押せなくしてある。段取りを説明文で伝えるだけにすると、順番を飛ばして全員を締め出す事故が起きる。**押せる/押せないで段取りそのものを表す。**

取り消しを常に置く。危ない操作の隣には、必ず引き返す道を用意する。

## pattern 選定

| 候補 / hybrid | 必要 task capability への適合 | 弱点 | a11y/fallback | 判定 |
|---|---|---|---|---|
| 面の縦積み (手作業 → 接続 → 入れ替え) | 作業の順序がそのまま画面の順序になる | 縦に長い | 各面に節ラベルを付け、飛べるようにする | **採用** |
| 接続 1 件を定義リストで | 1 つの対象の属性を並べる箇所。表にすると 1 行しかできない | — | 用語 + 説明の組 | **採用** |
| ウィザード (段階フォーム) | 途中で Google Cloud Console へ移るため、Hub 側で段を進められない時間が生まれる | — | — | 不採用 |

## 削った情報

- **client secret の本体** — 表示する用が無い。末尾 4 文字で見分けられる。
- **Google 側の設定内容の読み出し** — Hub から取得する経路が無く、出すと「Hub が把握している」ことになる。
- **接続の変更履歴** — 「最後に更新した日時」まで。全履歴は監査ログの担当。

## 視覚要素の意味契約

| 要素 | 採用/省略 | 伝える意味 | a11y 代替 |
|---|---|---|---|
| label | 採用 | 用語 + 説明。コピーボタンには何をコピーするかを名前に入れる | `<dt>/<dd>` / `aria-label` |
| line | 採用 | 面の枠のみ | — |
| space | 採用 | `comfortable`。緊張する画面なので詰めない | — |
| icon | 省略 | 状態はチップの語。危険な操作は色 (`danger`) と語の両方で示す | — |
| alignment | 採用 | 先頭揃え | — |
| repetition | 採用 | ボタンの並び・結果の返し方を接続カードごとに揃える | — |

**結果は押したボタンの側に返す。** カードの中には離れた 2 つのボタン群 (接続の操作 / 入れ替え) があり、カード 1 枚にまとめて出すと、狭い画面では結果が画面外で告知される。

コピーは成功したときだけ「コピーしました」と告知する。失敗を黙って成功に見せないよう、押した結果で状態を分ける。

## 成功指標と証跡境界

- 代表タスク: 「新しい secret を登録し、テストに通してから切り替える」。
- machine gate (現行): テスト未合格では有効化を押せないこと、secret 本体が DOM に出ないこと、日時が JST 固定であること、a11y テスト。
- manual gate: 入れ替え中に「現在のログインは継続している」ことが読めること。
- future gate (予定): 旧 secret の失効確認。Hub からは見えないため、当面は案内文で運用する。
