# S07-L ランディング入口 (`/`) 情報設計シート

## 利用文脈

3 種類の人が同じ URL に来る。

1. **未認証で初めて来た人** — テナント ID を知らないことがある。
2. **未認証で前にも来た人** — 端末に前回のテナントが残っている。1 手で通り抜けたい。
3. **サインイン済みだが作業場所が決まっていない人** — 複数の Workspace に所属していて、まだ選んでいない。

3 つとも「ここで止まらせない」のが目的。端末は wide / narrow の両方。

## 画面プロファイル

Surface: `S07-L.ROOT` / route: `/`。role、task-mode、density、wide/middle/narrow pattern、sticky policy は `docs/screen-inventory.md` の同 surface 行だけを正本とする。`S09-L.DASHBOARD` (`/dashboard`) は planned であり、current の既定着地は `/sheets`。

## 表示項目とグループ

### 未認証のとき

| 項目 | 表示加工 | 可視ラベル | accessible name/description |
|---|---|---|---|
| 見出し | 「サインイン」+「ご契約のテナント ID を入力すると、そのテナントのサインイン画面へ移動します。」 | — | — |
| 形式エラー | 「テナント ID の形式が正しくありません」+「半角の小文字英数字とハイフンだけが使えます (例: harness-hub)。」 | 見出しの語 | — |
| 前回のテナント | 端末に残っていれば 1 手のリンクとして出す。「違う場合は下のフォームから入力してください。」 | カード表題 | リンク名 = 「<slug> のサインイン画面へ進む」 |
| テナント ID | 入力欄。説明「サインイン画面の URL に含まれる識別子です (例: harness-hub)。分からない場合は管理者にお問い合わせください。」 | 「テナント ID」 | ラベル + 説明 |
| 稼働状況 | 「Hub の実行基盤は起動しています」+ `/health` への導線 | — | — |

### サインイン済みで作業場所が未確定のとき

| 状況 | 出すもの |
|---|---|
| 所属 2 件以上 | 「Workspace を選択」+ 所属の一覧。「選んだ Workspace はこの端末に記憶され、次回以降はそのまま業務画面へ移動します。」 |
| 所属 0 件 | 「作業できる Workspace がありません」+「テナントの管理者へ Workspace への追加を依頼してください。」 |

**所属 0 件を空の一覧で済ませない。** 選択肢の無いカードだけを出すと、なぜ進めないのか分からないまま行き止まりになる。状態を名指しし、次に誰へ何を頼めばよいかまで書く。

## 答えないこと

**「そのテナントが存在するか」をこの画面は決して答えない。** 形式が違うときだけ差し戻し、存在しないテナントを入れても同じ扱いにする。答えると、テナント名の総当たりで契約企業の一覧が作れてしまう。

差し戻したときに入力欄は**空にする**。前回値を残すと「自分が打っていない値が入ったまま『形式が正しくありません』と言われる」状態になり、どこを直せばよいか分からない。

Workspace の一覧には識別子をそのまま出す。名前を引くには業務データを読む必要があり、この画面は未認証でも到達できる公開経路として「業務データを一切含めない」前提で作ってある。出しているのは利用者自身の証明書に焼かれた値だけで、新たな読み取りは起きない。

## pattern 選定

| 候補 / hybrid | 必要 task capability への適合 | 弱点 | a11y/fallback | 判定 |
|---|---|---|---|---|
| 前回の導線 + 入力フォームの併置 | 2 回目以降は 1 手、初回は入力。3 種類の来訪者を 1 画面で捌ける | 縦にやや長い | どちらも JavaScript 無しで動く | **採用** |
| 入力フォームだけ | 毎回打たせることになる | — | — | 不採用 |
| 自動で前回のテナントへ飛ばす | 1 手も要らないが、テナントを変えたい人が入口に辿り着けない | — | — | 不採用 |

**この画面は JavaScript 無しで動く。** 入力は通常の GET フォーム、Workspace の選択は通常のリンクで作ってある。サインイン直後のこの画面が、JavaScript の読み込み完了まで機能しない状態を作らない。

## 削った情報

- **サービスの説明・機能紹介** — 通過点であり、読ませるものを置かない。
- **テナントの一覧・検索** — 存在有無を答えないという方針と矛盾する。
- **Workspace の表示名** — 上記のとおり、公開経路で業務データを読まないため。残課題。

## 成功指標と証跡境界

- 代表タスク: 「前回のテナントで 1 手でサインイン画面へ進む」/「複数所属のうち 1 つを選んで業務画面へ入る」。
- machine gate (現行): この経路が要求ごとに描画されること (静的化に倒れると本番で落ちる)、形式エラー時に入力欄が空になること、所属 0 件で案内が出ること。
- manual gate: JavaScript を切った状態でも入口として機能すること。
- future gate (予定): Workspace の表示名。公開経路の制約を崩さない解決口が要る。
