# S09 効果測定ダッシュボード 情報設計シート

## 利用文脈

workspace-admin / provider-admin。月次の報告前や予算の説明前に開き、「どれだけ効果が出ているか」を数字で掴む。**全体の量 → 推移 → 内訳 → 個別のツール**という読む順があり、途中で期間を変えて何度も読み直す。端末は wide が主 (報告資料へ転記するため)。

## 画面プロファイル

Surface: `S09.METRICS` / route: `/metrics`。role、task-mode、density、wide/middle/narrow pattern、sticky policy は `docs/screen-inventory.md` の同 surface 行だけを正本とする。管理者は主要 persona だが、current API の集計閲覧 capability は member 以上である。

## 表示項目とグループ

| グループ | 項目 | 顕著度 | 表示加工 | 可視ラベル | accessible name/description |
|---|---|---|---|---|---|
| 操作 | 開始日 / 終了日 | — | 日付欄。共通の `FilterBar` に載せる | 「開始日」「終了日」 | 入力欄のラベル |
| 総量 | 総実行回数 / 減らせた時間 / 減らせた金額 / 使われたツール数 | — | `KpiCard`。単位を値の外に置く | カードのラベル | ラベル + 値 + 単位 |
| 総量 | 使われている割合 | — | 母数 0 のとき `—`。このとき単位 `%` も外す | 「使われている割合」 | — |
| 推移 | 実行回数と削減時間 | — | 折れ線 | グラフ表題 | 表題 |
| 内訳 | ツール別の削減額 | — | 棒 | グラフ表題 | 表題 |
| 内訳 | 部門別の削減額 | — | ドーナツ | グラフ表題 | 表題 |
| 個別 | 業務ツール | (見出し) | 列を sticky、幅 `16rem` | 列見出し | — |
| 個別 | 減らせた金額 | lead | 円。並べ替えの既定 | 列見出し「減らせた金額 (円)」 | — |
| 個別 | 減らせた時間 | context | 時間 | 列見出し「減らせた時間 (時間)」 | — |
| 個別 | 実行回数 | metadata | 回 | 列見出し「実行回数」 | — |

表の列順は「業務ツール → 実行回数 → 時間 → 金額」だが、顕著度はその逆順に近い。**金額がこの画面の主指標**で、並べ替えの既定でもあるため、カードでは名前の直後に置く。実行回数は金額・時間を作る内訳の数字なので最後で足りる。

「使われている割合」の母数 0 は「1 つも使われていない (= 0%)」ではなく**そもそも数える対象が無い**状態である。両者は打ち手がまるで違うので、`0%` ではなく `—` を出し、単位も外す (`—%` は再び意味が読めなくなる)。

## pattern 選定

| 候補 / hybrid | 必要 task capability への適合 | 弱点 | a11y/fallback | 判定 |
|---|---|---|---|---|
| chart+table (wide/middle) | 総量 (KPI) → 形 (グラフ) → 個別の値 (表) を 1 画面で辿れる。報告への転記は表の値から行う | 縦に長い | グラフは表題を持ち、同じ値が下の表にもある (グラフだけが値の唯一の出口にならない) | **採用** |
| chart+card-collection (narrow) | ランキング表を 1 件ずつのカードへ畳む。金額の大きい順という並びは縦の順序として残る | ツールどうしの見比べはできない | `narrowAs="card-collection"` 1 か所で切り替える | **採用** |
| table のみ | 推移の形が読めない。月次報告では「増えているか」が要る | — | — | 不採用 |

数値はすべて API が返した確定値をそのまま出す。この画面での算術は表示整形と並べ替えだけで、時間・金額の換算は行わない (換算はサーバ側の 1 経路に閉じる)。

## 削った情報

- **利用者ごとの実績** — 個人の比較を目的にしない。部門別までで止める。
- **ランキングの全件** — 上位のみ (`topRanking`)。全件は S16 の週次レポートで扱う。
- **生の実行ログ** — この画面は集計を読む場所であり、1 件ずつの追跡は別の画面の役割。

## 視覚要素の意味契約

| 要素 | 採用/省略 | 伝える意味 | a11y 代替 |
|---|---|---|---|
| label | 採用 | KPI のラベル・グラフ表題・列見出し。単位は値と分けて置く | — |
| line | 採用 | 折れ線は時間の連続。表では行の境界のみ | グラフと同じ値を表にも出す |
| space | 採用 | `balanced`。KPI 帯 / グラフ帯 / 表の 3 ブロックを余白で分ける | — |
| icon | 省略 | 増減の矢印は使わない。比較の基準を持たない画面で矢印を出すと根拠のない評価になる | — |
| alignment | 採用 | 数値列はすべて右揃え。桁を比べるため | — |
| repetition | 採用 | 絞り込み帯の形とボタンの語 (「絞り込む」) を全画面で揃える | — |

グラフの色は系列の識別のみを意味し、良し悪しは表さない。色だけで意味を伝える箇所は作らない。

## 成功指標と証跡境界

- 代表タスク: 「先月の削減額と、その内訳で一番大きいツールを言えるようにする」。
- machine gate (現行): `MT-VM-011/012` (母数 0 と実績 0 の出し分け)、a11y テスト、狭い画面でカードが描かれること。
- manual gate: 期間を変えたときに KPI・グラフ・表がすべて同じ期間を指していること。
- future gate (予定): 前期間との比較 (増減) を出すか。基準の決め方を先に決める必要があるため今回は出さない。
