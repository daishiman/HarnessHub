# S07 サインイン 情報設計シート

## 利用文脈

全員 (未認証)。**この画面に用は無い。** 目的地は別にあり、ここは通過点である。したがって画面の目的は「1 手で通り抜けさせる」ことだけで、読ませることではない。端末は wide / narrow の両方。

## 画面プロファイル

Surface: `S07.SIGNIN` / route: `/[tenant_slug]/signin`。role、task-mode、density、wide/middle/narrow pattern、sticky policy は `docs/screen-inventory.md` の同 surface 行だけを正本とする。

## 表示項目とグループ

| 項目 | 表示加工 | 可視ラベル | accessible name/description |
|---|---|---|---|
| テナントの表示名 | サインインボタンの文言に埋め込む (「<表示名> でサインイン」) | ボタンの語 | ボタン名 |
| サインイン | ボタン 1 つ。押すと外部の認証基盤へ移る | 「<表示名> でサインイン」/ 準備中は「サインインを準備中…」 | 押下中は `aria-busy` |
| 失敗の告知 | 「サインインを開始できませんでした」+「通信状態を確認して、もう一度お試しください。」 | 見出しの語 | 割り込みで読み上げる (`assertive`) |

**押せる場所を 1 つにする。** 認証は外部の基盤に委ねており、この画面で選ばせることは何も無い。入力欄も選択肢も置かない。

テナントの表示名をボタンに入れる。どの会社としてサインインしようとしているかが、押す直前に読める。URL のテナント名だけでは、間違ったテナントの画面に来ていることに気づけない。

失敗は割り込みで読み上げる。押した直後に何も起きなければ、次の操作へ進みようがないため、通常の告知 (順番待ち) では遅い。

## 遷移先の決め方

| 入力 | 扱い |
|---|---|
| `?returnTo=` の相対 path (同一 origin) | そのまま遷移先にする |
| 絶対 URL / スキーム付き / `//` 始まり | **既定の着地へ落とす** (外部サイトへ飛ばされるのを防ぐ) |
| 指定なし | 既定の着地 |

遷移先は最初は既定値で持ち、画面が動き出してから確定させる。サーバ側では現在の URL を読めず、先に読もうとすると初回描画が食い違う。

## pattern 選定

| 候補 / hybrid | 必要 task capability への適合 | 弱点 | a11y/fallback | 判定 |
|---|---|---|---|---|
| ボタン 1 つ | 通過点として最短。押し間違えようがない | 選択肢が増えたときに拡張が要る | 通常のフォーム送信で外部へ移る。JavaScript が要るのは事前準備だけ | **採用** |
| ID とパスワードの入力 | 認証基盤を二重に持つことになり、退職者の締め出しが 2 箇所になる | — | — | **不採用** (方針として採らない) |
| 認証方式の選択肢を並べる | 現状 1 方式しかなく、選ばせる意味が無い | — | — | 不採用 |

## 削った情報

- **サービスの説明・機能紹介** — 通過点に読むものを置くと、押す場所が下へ押し出される。
- **利用規約へのリンク** — 別の静的ページが持つ。ここへ並べると押す先が 2 つになる。
- **「パスワードを忘れた」導線** — パスワードを持たないため存在しない。置くと方式を誤解させる。

## 成功指標と証跡境界

- 代表タスク: 「押して外部の認証画面へ移る」。
- machine gate (現行): 遷移先の検査 (絶対 URL を既定へ落とすこと) の単体テスト、a11y テスト、二重送信を防ぐこと。
- manual gate: 失敗したときに割り込みで読み上げられること。
- future gate (予定): 認証方式が増えたときの選択の出し方。
