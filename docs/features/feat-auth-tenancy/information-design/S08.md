# S08 端末の承認 情報設計シート

## 利用文脈

signed-in member 以上 (current API capability)。手元の道具 (Publisher / CLI) に確認コードが表示され、「このページを開いて入力してください」と案内されて来る。**別の画面を見ながらコードを写す**のが実態で、ブラウザとその道具を行き来する。1 分以内に終わらないと、コードの有効期限が切れる。owner 限定は planned の別判断とし、この sheet で current role を変更しない。端末は wide が主。

## 画面プロファイル

Surface: `S08.DEVICE` / route: `/device`。role、task-mode、density、wide/middle/narrow pattern、sticky policy は `docs/screen-inventory.md` の同 surface 行だけを正本とする。owner 限定は current API contract ではなく、製品判断待ちの planned 変更である。

## 表示項目とグループ

| 項目 | 表示加工 | 可視ラベル | accessible name/description |
|---|---|---|---|
| 見出し | 「端末を承認する」+ 説明「Publisher または CLI に表示された 8 文字の確認コードを入力してください。」 | — | 節の名前 |
| 確認コード | 入力欄。説明「英数字8文字です。空白やハイフンは取り除いて送信します。」。大文字入力・自動補完 (ワンタイムコード)・つづり検査なし | 「確認コード」 | ラベル + 説明 |
| 承認する Workspace | 選択欄。説明「この端末が操作するWorkspaceを選びます。」 | 「承認するWorkspace」 | ラベル + 説明 |
| 実行 | 「この端末を承認する」 | ボタンの語 | — |
| 結果 | 成功 / 7 種類の失敗を言い分ける | 見出しの語 | 失敗は割り込みで読み上げる |

**入力の揺れを画面側で吸収する。** 別画面から写すので、空白やハイフンが混ざる。取り除いてから送ることを説明にも書き、「なぜか通らない」を作らない。ワンタイムコードとして自動補完を効かせ、つづり検査を切り、大文字で入力させる。

コードが URL に含まれて来た場合は入力欄に埋めておく。案内に従って来た人が、もう一度写す必要をなくす。

## 失敗の言い分け

7 通りを別々の文面で出す。同じ「承認できません」にまとめると、**次に何をすればよいか**が変わるのに読み手には同じに見える。

| 失敗 | 次にすること |
|---|---|
| 形式が違う | 8 文字を確認して打ち直す |
| サインインしていない | サインインし直す |
| 権限か試行回数 | 道具の側で最初からやり直す |
| コードが見つからない | 打ち直すか、新しいコードを発行する |
| 使用済み | 新しいコードを発行する |
| 期限切れ | 新しいコードを発行する |
| 通信できない | 時間をおいて再試行する |

打ち直しで直るもの (形式・見つからない) は注意、やり直しが要るもの (権限・通信) は警告と、色でも段を分ける。ただし色だけには頼らず、見出しの語で必ず言い分ける。

成功したら入力欄を空にする。同じコードが残っていると、続けてもう 1 台承認しようとしたときに古い値を送ってしまう。

## pattern 選定

| 候補 / hybrid | 必要 task capability への適合 | 弱点 | a11y/fallback | 判定 |
|---|---|---|---|---|
| 1 画面のフォーム (2 項目) | 別画面を見ながら 1 分以内に済ませる用に合う | — | 結果は同じ画面に返す | **採用** |
| コードを 8 マスに分けた入力 | 見た目は分かりやすいが、貼り付けと読み上げが壊れやすい | — | — | 不採用 |
| Workspace を自動で決める | 手数は減るが、複数ある人が意図しない場所へ端末をつなぐ | — | — | 不採用 |

## 削った情報

- **端末の詳細情報 (OS・IP)** — 承認の判断は手元の道具に出ているコードとの一致で行う。並べても照合の材料にならない。
- **過去に承認した端末の一覧** — この画面の用は 1 台を通すこと。一覧は管理側の役割。
- **有効期限の残り時間** — 秒読みを出すと焦らせるうえ、切れたときの案内 (期限切れ) で足りる。

## 成功指標と証跡境界

- 代表タスク: 「道具に出たコードを写して 1 台を承認し、道具へ戻る」。
- machine gate (現行): 入力の正規化と形式検査の単体テスト、応答の種別ごとに文面が変わること、a11y テスト。
- manual gate: 空白やハイフン付きで貼り付けても通ること。
- future gate (予定): Workspace の選択肢に名前を出す。現状は識別子のまま (名前の解決口がまだ無い)。
