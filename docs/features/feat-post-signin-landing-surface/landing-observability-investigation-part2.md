# post-signin landing observability 詳細調査履歴 (2/3)

正規 contract: [`specs/harness-hub-post-signin-landing-observability-contract.md`](../../../specs/harness-hub-post-signin-landing-observability-contract.md)。索引: [index](./landing-observability-investigation.md)。他パート: [part1](./landing-observability-investigation-part1.md) · [part3](./landing-observability-investigation-part3.md)。

## 3. 着地先と着地画面 (利用者の直接決定)

### 3.1 既定着地 = `/dashboard` (appr-034)

独立監査が「既定着地 `/sheets` は利用者の承認にも AI への委任範囲にも紐付いていない」と指摘したため、利用者へ 3 択を提示し直接決定を得た。

| 選択肢 | 開示したコスト |
|---|---|
| `/sheets` を維持 | 実装量の増加なし |
| `/catalog` | 業務ツール一覧へ着地 |
| **`/dashboard` を先に作る (選択)** | 稼働状況・最近の作業をまとめた画面を新規に作る。S09 で予定されている段階の前倒しになり実装量が増える |

利用者は実装量増を了解のうえ `/dashboard` を選択した。

**前倒しするのは S09 の全体ではない。** S09 (KPI・推移・完了率・ランキング・部門別削減) は P5 のまま据え置き、着地に必要な部分だけを先に作る。詳細は `docs/frontend-spec.md` §10。

### 3.2 着地画面の内容 (appr-035)

独立監査は続けて「着地先の選択は承認されたが、その画面が何を表示するかは委任範囲外なのに AI が代理確定している」と指摘した。全選択肢のコストを対称に開示したうえで利用者へ 3 問を提示し、以下を得た。

| # | 論点 | 決定 | 権限 |
|---|---|---|---|
| a | 所属コンテキスト | 常時表示し、複数所属ならその場で切り替えられる | 利用者本人 |
| b | 行き止まり回避 | 既存業務画面群への導線を必ず持つ | AI 代理 (選択肢が一意) |
| c | 最近の作業 | 自分が最後に触ったものを種別横断で更新日時順に | 利用者本人 |
| d | 稼働状況 | 通常時は出さず、異常時だけ出す | 利用者本人 |
| e | scope 未解決時 | 生の 403 でなく回復手段を提示する | AI 代理 (選択肢が一意) |
| f | 認証基盤不可用時 | 利用者の操作ミスに見える文言で表示しない | AI 代理 (選択肢が一意) |

**d は本不具合の直接の是正である。**「稼働状況しか出ない」は稼働状況が主役に据えられた画面へ縮退した結果であり、利用者が d を選んだことで **「稼働状況が主役の画面は正常な着地先ではない」が仕様要求として確定した**。

f は権限不足 (403) で再サインインへ誘導しない契約と同根である。誘導するとループになり、利用者は永久に業務画面へ到達できない。

### 3.3 3.2 の決定を取るときに何を見せたか (記録上の開示)

独立監査が「AI が『(推奨)』ラベルを付けて誘導していないか、記録からは検証できない」と指摘した。事実を開示する。

**実際に提示した 3 問とも、先頭の選択肢に「（推奨）」ラベルが付いていた。そして 3 問とも先頭が選ばれた。** さらに 3 問とも、先頭選択肢の説明を「今回の症状を直接解決する」という同じ言い回しで締めていた。選択肢ごとのコストとトレードオフは対称に開示していたが、この 2 点の偏りは残る。

そのうえで 3.2 の決定は取り消さない。コスト開示は対称で、利用者は実装量が増える側を了解して選んでいる。とくに d (稼働状況は異常時だけ) は、利用者が最初に報告した症状の是正そのものであり、推奨が無くても同じ結論に至る性質のものである。**ただし本節を読んで再考したい場合、いずれの決定も差し戻せる。この開示は追認を求めるものではない。**

以後、提示した質問文は推奨ラベルの有無を含めて逐語で記録する。AI の要約だけでは、後から誰も中立性を検証できない。

### 3.4 変更しないもの

先行仕様の契約 (相対 path のみ許可・open redirect 防止・認証済みで `/` に来たら着地先へ・scope 解決・所属 workspace が 1 件なら選択画面を挟まない) は一切変更しない。**既定着地の値だけ**が変わる。

実装上の唯一の正本は `apps/hub/src/lib/routing/post-signin-landing.ts` の `DEFAULT_POST_SIGNIN_LANDING`。テストは値を書き写さずこの定数を import する。二重管理でずれると、検査が症状を見逃す側に倒れる。
