# ドキュメントの新規作成 (`/docs/new`) 情報設計シート

## 利用文脈

workspace-admin / provider-admin。業務ツールの使い方や運用手順を書き起こす。**書くこと自体に時間がかかる**画面で、開いてから保存まで数十分かかることもある。書きながら見た目を確かめたい。端末は wide が主。

この画面は S15 の route surface variant として台帳に登録済み。

## 画面プロファイル

Surface: `S15.NEW` / route: `/docs/new`。role、task-mode、density、wide/middle/narrow pattern、sticky policy は `docs/screen-inventory.md` の同 surface 行だけを正本とする。

## 表示項目とグループ

| 項目 | 表示加工 | 可視ラベル | accessible name/description |
|---|---|---|---|
| スコープ | 選択欄。「テナント」「共通 (要 provider-admin 権限)」。既定はテナント | 「スコープ」 | ラベル |
| タイトル | 自由入力 | 「タイトル」 | ラベル |
| 本文 | Markdown 編集欄 (16 行)。書式のプレビューを持つ | 「本文」 | ラベル |
| 実行 | 「作成する」/ 実行中は「作成しています…」 | ボタンの語 | — |
| 失敗 | 「作成エラー」+ 理由 | 見出しの語 | — |

**権限が要る選択肢に、その旨を選択肢の文言へ入れてある** (「共通 (要 provider-admin 権限)」)。選んでから拒否されるより、選ぶ前に分かるほうが早い。選択肢を隠さないのは、共通ドキュメントという区分が存在すること自体は知っておいてよいため。

作成できたら閲覧画面へ移る。作成した本人が最初にすることは「書いたものを読み返す」ことなので、一覧へ戻さない。

## pattern 選定

| 候補 / hybrid | 必要 task capability への適合 | 弱点 | a11y/fallback | 判定 |
|---|---|---|---|---|
| 1 画面のフォーム + Markdown 編集欄 | 3 項目しかなく、時間がかかるのは本文だけ。本文に画面を大きく使える | — | 編集欄は遅れて読み込む。読み込み中も告知する | **採用** |
| 段階フォーム | 3 項目で段に分ける意味が無い | — | — | 不採用 |
| リッチテキスト編集 | 見た目は分かりやすいが、保存形式が Markdown なので変換で情報が落ちる | — | — | 不採用 |

編集部品は開いてすぐには読み込まない。初回の読み込み量を抑えるためで、読み込み中は「Markdown エディタを読み込んでいます…」を読み上げ領域に出す。無言で空欄が出ると、壊れているように見える。

## 削った情報

- **下書きの自動保存** — 未実装。数十分かける画面なので必要性は高い。**残課題**。
- **AI による下書き生成** — 台帳では S15 の機能として挙がっているが、この画面には未接続。
- **公開状態の選択** — 新規作成は必ず下書きから始まる。ここで選ばせると、書き上がる前に公開する事故が起きる。

## 視覚要素の意味契約

| 要素 | 採用/省略 | 伝える意味 | a11y 代替 |
|---|---|---|---|
| label | 採用 | 入力欄のラベル。権限の要否は選択肢の文言に書く | `<label>` |
| line | 省略 | 3 項目しかなく区切る必要が無い | — |
| space | 採用 | 入力欄どうしの間隔は共通の縦積み部品に任せる。画面ごとに余白を書かない | — |
| icon | 省略 | 失敗は見出しの語で伝える | — |
| alignment | 採用 | 先頭揃え | — |
| repetition | 採用 | ボタンの語・エラーの出し方を他のフォームと揃える | — |

## 成功指標と証跡境界

- 代表タスク: 「手順書を 1 本書いて作成し、閲覧画面で読み返す」。
- machine gate (現行): a11y テスト、編集部品の読み込み中に告知が出ること。
- manual gate: 数十分書いた後に保存できること (時間切れで失われないこと)。
- future gate (予定): 下書きの自動保存。
