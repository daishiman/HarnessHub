# S15 ドキュメント一覧 情報設計シート

## 利用文脈

member 以上。「業務ツールの使い方を調べる」ために来る。探し方はタイトル、スコープ、公開状態、カテゴリ、タグ。
wide / middle では公開状態と更新日時を行どうしで比べ、タイトル列のthumbnail・excerpt・分類・本文資産バッジで
開く前の判断を補う。narrow では 1 件を読み切ってから次へ進む。最後に **1 本を選んで読み切る**ことが共通の完了状態。

## 画面プロファイル

Surface: `S15.LIST` / route: `/docs`。role、task-mode、density、wide/middle/narrow pattern、sticky policy は `docs/screen-inventory.md` の同 surface 行だけを正本とする。

## 表示項目とグループ

| グループ | 項目 | 顕著度 | 表示加工 | 可視ラベル | accessible name/description |
|---|---|---|---|---|---|
| 操作 | スコープ / 状態 / カテゴリ / タグ / タイトル検索 | — | `絞り込む` で確定し、次に来たときまで覚える。category/tag は完全一致、tag は1件、検索はタイトルのみ | 各入力の語 | 入力ラベル + 補足 |
| 識別 | タイトル / thumbnail | (見出し) | 詳細へのリンク。認証必須の内部画像または安全なhttp(s)画像だけを装飾的thumbnailで表示 | — | リンク名 = タイトル。thumbnailは空alt |
| 判断 | 状態 | context | 「非公開」「予約中」「公開」。予約中は保存enumでなく `draft + future publish_at` から導出し、予約日時も出す | バッジの語 | バッジの語 + 予約日時 |
| 判断 | スコープ | context | `ScopeChip` (「共通」「テナント」) | チップの語 | チップの語 |
| 判断 | カテゴリ / タグ / 派生元 | context | category、各tag、manual thumbnail/excerptの「編集済み」をbadge表示 | バッジの語 | バッジの語 |
| 要約 | excerpt / asset summary | metadata | excerptは最大2行。画像件数・表・コードの有無をbadge表示 | 要約文 / badge | 文字列そのもの |
| 経過 | 更新日時 | metadata | `formatDateTime` (JST 固定・時計名つき) | 「更新日時」 | 用語 + 説明の組 |

状態とスコープは、wide/middle では列、narrow ではカードの表題直下に置く。カテゴリ・タグ・excerpt・
asset summary は独立列を増やさずタイトル列へまとめる。比較に必要な4列を保ったまま、読む判断材料を落とさないためである。

更新日を日付だけから日時へ変えている。同じ日に何度も直される文書があり、日付だけだと同じ文字列が並んで、新しい順に並べても順序の根拠が画面から消える。

## pattern 選定

| 候補 / hybrid | 必要 task capability への適合 | 弱点 | a11y/fallback | 判定 |
|---|---|---|---|---|
| table (wide/middle) | 公開状態と更新日時を行どうしで比べられる。タイトル列に固定幅を持たせず、余りを使う | narrow では 4 列の比較が成立しない | `stickyHeader`。列見出しと同じ語をカードの項目名に引き継ぐ | **採用** |
| card-collection (narrow) | タイトルを起点に 1 件を読み切れる | 行どうしの比較はできない | `DataTable narrowAs="card-collection"` で同一データから描画する | **採用** |
| master-detail | 一覧を残したまま本文を読める | 左ペインを半分に狭めると、table を採った理由 (行どうしの比較) が成立しなくなる | 連続閲覧需要は未観測。観測時はまず詳細側の前後送りを検討する | **不採用 (却下)** (`HarnessHub-ydf8`) |

current の判定は **wide/middle = table / narrow = card-collection**。タイトル列だけは固定幅を持たず、適用範囲・状態・更新日時の幅を固定して余りを吸収する (`apps/hub/tests/ui-foundation/list-ergonomics.test.tsx` LISTERG-06)。

### master-detail 不採用の決着 (2026-08-12, `HarnessHub-ydf8`)

起票時の決着条件は「文書を続けて何本も読む使い方が実際にあるかの実測」だった。これを次の 2 点で置き換えて却下と判定する。

1. **wide/middle の table 採用と構造的に両立しない。** master-detail の左ペインは画面の半分以下になる。table を採った理由は「公開状態と更新日時を行どうしで比べられる」ことだが、半分幅では 4 列のうちタイトル列が押し潰され、比較のために採った形が比較できなくなる。一方で右ペインには `documents.body_markdown` (長さの上限を持たない本文) が入るため、両ペインが同時に狭いという弱点は緩和されない。この非両立は利用実測を待たずに決まる。
2. **決着条件が実行不能なまま滞留している。** 「続けて何本も読む使い方があるか」は行動計測を要するが、計測基盤は現時点で存在しない (`apps/hub/src/lib` に画面操作の計測経路が無い)。1 つの配置判断のために計測基盤を新設するのは釣り合わない。

現行の代表タスクは「共通の公開済み手順書を 1 本開いて読み切る」であり、一覧へ戻らず次を読む前後送りは必須依存ではない。**一覧の並び順を引き継ぐ前後送り**は、連続閲覧の需要が観測されたときに、画面を分割する master-detail を再考するより先に評価する future 案とする。前後送りでも需要を満たせない根拠が得られた場合に限り、次の再考条件と合わせて master-detail 判定を開けなおす。

- 前後送りの利用が「詳細を開いた回数」の相当割合を占め、かつ一覧へ戻る操作が減ったことが計測できたとき (計測基盤が入った後)。
- 1 文書あたりの本文長の中央値が、右ペイン幅で 1 画面に収まる程度まで短くなったとき (長文と狭ペインの弱点が消えるため)。

## 削った情報

- **作成者** — 誰が書いたかで読む本を選ばない。詳細で確認できる。
- **本文全文** — 一覧応答を重くし、検索理由も分かりにくくなる。最大400文字のexcerptとasset summaryだけを返す。
- **複数タグのAND/OR検索** — APIは単一 `tag` の完全一致だけを受ける。必要性が観測されるまで検索構文を増やさない。

以前の一覧情報を最小化する判断は、現在の実装（分類・要約カードと category/tag filter）により
supersede（置き換え済み）となった。件数増加を待つfuture案ではない。

## 視覚要素の意味契約

| 要素 | 採用/省略 | 伝える意味 | a11y 代替 |
|---|---|---|---|
| label | 採用 | 更新日時は「用語 + 説明」の組で出し、日付だけを裸で置かない | `<dt>/<dd>` |
| line | 採用 | wide/middle は行と列見出しの境界、narrow はカードの枠に使う | — |
| space | 採用 | `balanced`。narrow のカードでも読む順を保つ | — |
| icon | 省略 | 状態・スコープとも語で伝える。色だけのチップにしない | — |
| alignment | 採用 | すべて先頭揃え | — |
| repetition | 採用 | 絞り込み帯・空状態・カーソル送りを他の一覧と同じ形にする | — |

0 件の言い方を「絞り込んだ結果の 0 件」と「そもそも 1 本も無い」で分ける。前者に「まだありません」と出すと、条件を外せば見つかるものまで存在しないと読める。

空状態の次の操作も同じ区別に従う。未絞込で 0 件かつ `docs.write_tenant` を持つ利用者には
`/docs/new` への「最初のドキュメントを作成」を出す。作成権限がない利用者には操作を偽装せず、
`workspace-admin` 以上が必要であることを説明する。絞り込み結果が 0 件のときは作成導線より
「絞り込みを解除」を優先し、全条件と cursor 履歴を初期化して一覧を再取得する。

読み込めなかったときは件数を読み上げない。「0 件」と「失敗」の取り違えを、画面だけでなく音声でも起こさないため。

## 成功指標と証跡境界

- 代表タスク: 「共通の公開済み手順書を 1 本開いて読み切る」。
- machine gate (現行): a11y テスト (`apps/hub/tests/docs-cms/a11y-screens.test.tsx`)、権限あり/なしと未絞込/絞込 0 件の次操作 (`apps/hub/src/__tests__/docs-cms/document-screens-interaction.test.tsx` DOCS-UI-030..032)、日時が JST 固定であること (`apps/hub/tests/ui-foundation/datetime-format.test.ts`)、絞り込み条件の復元前に問い合わせないこと、列構成とタイトル列に幅を持たせないこと (`apps/hub/tests/ui-foundation/list-ergonomics.test.tsx` LISTERG-06)。
- manual gate: 詳細から戻ったときに絞り込み条件が保たれていること。
- future gate (条件付き): 連続閲覧需要が観測され、詳細画面の前後送り (一覧の並び順を引き継ぐこと) を導入する場合の導線テスト。現代表タスクの必須 gate ではない。master-detail の要否そのものは `HarnessHub-ydf8` で不採用に決着済みで、再考条件は「pattern 選定」節に置く。
